# Misattitude — クローズドテスト準備チェックリスト

クローズドテスト（または内部テスト）を Google Play Console で開始するために
必要な作業の一覧。所要時間と依存関係を一緒に書いているので、上から順に進めれば
最短ルートになる。

---

- [ ] [Google Play Console](https://play.google.com/console) でデベロッパー登録
  - 個人 / 法人どちらでも可。**初期費用 $25 (一括)**

- [ ] アカウントが「Active」状態になったことを確認

## 3. 必須コンテンツ (App content)【必須】

Play Console 内「アプリのコンテンツ」セクション。1 つでも未完了だと公開不可。

### 3-1. プライバシーポリシー URL【必須】
- [ ] `doc/playstore/privacy-policy.md` を HTML/Markdown のままどこかにホスト
  - 推奨：GitHub Pages（リポジトリの Settings → Pages を有効化）
  - 代替：Notion 公開ページ、Google Sites、自分のドメイン
- [ ] URL を Play Console に入力

### 3-2. アプリへのアクセス権【必須】
- [ ] 「特別なアクセス手順は不要」を選択 (このアプリはログイン不要)

### 3-3. 広告【必須】
- [ ] 「いいえ、広告は含まれていません」

### 3-4. コンテンツのレーティング【必須】
- [ ] レーティング質問票に回答 (5〜10 分)
  - カテゴリ：ユーティリティ / 教育（暴力・性的表現なし）
  - 想定レーティング：**全年齢対象 (IARC 3+)**

### 3-5. 対象年齢層【必須】
- [ ] 13 歳以上 (一般向け / 教育用ツール)

### 3-6. データセーフティ【必須】

⚠️ AdMob を組み込んだので、もはや「データを一切収集しない」とは申告できない。
Google AdMob による収集を正直に申告する必要がある（Google 自身の SDK だが、
データ収集者は Google であって本アプリ開発者ではない、という整理）。

- [ ] 「データを収集または共有しますか？」→ **はい**
- [ ] 収集データの分類：
  - **「アプリ アクティビティ」→「アプリの操作」** — AdMob が広告表示・
    クリックを計測するため。共有：はい。任意：いいえ（広告表示の必要要件）
  - **「アプリの情報とパフォーマンス」→「クラッシュ ログ」** — Google Play
    Services 経由で軽微な診断データが共有される可能性。共有：はい
  - **「デバイス または他の ID」→「デバイス または他の ID」** —
    Android Advertising ID。AdMob による広告配信に必須。共有：はい。
    収集対象（任意か必須か）：「必須」
- [ ] **収集していないもの** はチェックを外しておく：
  - 氏名・メアド・電話番号などの個人情報
  - 位置情報（厳密な位置情報。AdMob の収集は IP ベースの「おおよその国・地域」
    なので、Google の SDK ガイダンスでは「位置情報を収集していない」扱いで OK）
  - 写真・動画・音声・連絡先・カレンダー・ヘルス・財務・メッセージング 等
- [ ] 「データは送信中に暗号化されますか？」→ **はい**（AdMob / Play Billing
  ともに HTTPS）
- [ ] 「ユーザーがデータの削除を要求できますか？」→ **はい**
  - Android 設定 → Google → 広告 から広告 ID の削除可能
  - プライバシーポリシーの「7. 利用者の選択」セクションを参照
- [ ] セキュリティ慣行：HTTPS 暗号化通信のみ、独自のサーバーへの送信なし

### 3-7. ターゲット ユーザー【必須】

### 3-8. 政府機関アプリ【必須】

## 4. ストアの掲載情報 (Store listing)【必須】

Play Console → 「メインのストア掲載情報」

- [ ] 短い説明 (80 文字以内) — `doc/playstore/store-listing.md` 参照
- [ ] 詳細な説明 (4000 文字以内) — 同上
- [ ] アプリのアイコン (512×512 PNG, 32-bit, α無しの方が無難)
- [ ] **フィーチャー グラフィック** (1024×500 PNG／JPG、α 不可) — 別途作成必要
- [ ] スクリーンショット (スマートフォン)：最低 2 枚、最大 8 枚、各 320〜3840 px
  - 推奨スクリーンショット案：`doc/playstore/store-listing.md` 末尾に列挙

- [ ] タブレット用スクリーンショット (7 インチ / 10 インチ各最低 1 枚)

## まとめ：最速ルート

最も少ない手順で「テスターに配布できる状態」までいくなら：

1. **Play Console 登録** ($25 + 本人確認、数日)
2. **プライバシーポリシーを GitHub Pages にホスト** (10 分)
3. **アプリ作成 + 必須コンテンツ全部入力** (30 〜 60 分)
4. **アイコン・フィーチャーグラフィック・スクリーンショット 2 枚を準備** (1〜2 時間、または既存 `scr_*.png` を流用)
5. **AAB をアップロード → 内部テストで公開** (10 分)
6. **テスター招待リンクを共有** (1 分)

→ アカウント登録待ちを除けば、**実作業 2 〜 3 時間**でテスター配布可能。
